Getting started

            
LogoWriter GL follows the 1986 LogoWriter layout. A page has two sides:

            
    
              
  • Front is the turtle canvas, with the command center under it. Anything you type there runs right away on turtle 0.
    • 
              
  • Flip side holds procedures, written as TO name :input … END. Nothing else can go there.
    • 
            

            
Run clears the screen, resets to a single turtle at home, loads the flip side and calls STARTUP if you defined one. Pick a page from the Page menu to load one of 32 examples, grouped into classics, fractals, complex-plane sets, curves and turtle swarms; it starts immediately. Errors appear in the command center with the flip-side line number.

            
TO STARTUP
  CS
  REPEAT 5 [STAR 80 RT 72]
END

TO STAR :size
  REPEAT 5 [FD :size RT 144]
END

            
Try commands such as REPEAT 36 [SQUARE 100 RT 10] in the command center after loading the Squares page. Up and Down recall earlier commands.

          


          

            
Saving your work

            
    
              
  • Save stores the flip side under the name in the box. Saved pages appear under My pages in the Page menu. Saving with the same name replaces the earlier version.
    • 
              
  • Your current edit is also kept as a draft automatically and comes back when you reopen this page.
    • 
              
  • Both live in this browser only. They don't follow you to another device or browser, and clearing site data removes them. Private windows may not keep them at all.
    • 
              
  • For anything you want to keep for good, use Copy and paste the procedures into a file or repo. Open file… (or dropping a file on the editor) loads it back.
    • 
              
  • This page itself is saved in your Claude artifacts, and you can share it from its Share menu. Other people get the examples, not your saved pages.
    • 
            

          


          

            
Many turtles

            
LAUNCH [ instructions ] creates a new turtle at the launching turtle's position, heading, pen and color, then runs the list on it at the same time as everything else. Every turtle gets a turn each frame, so all of them move together.

            
TO STARTUP
  CS HT
  REPEAT 12 [LAUNCH [SPOKE REPCOUNT]]
END

TO SPOKE :i
  SETH :i * 30
  SETPC :i
  REPEAT 200 [FD 2 RT :i / 4]
  DIE
END

            
    
              
  • Inputs and LOCAL variables visible at the LAUNCH are copied into the new turtle, so each one keeps its own REPCOUNT or :i. Globals (MAKE outside a procedure's locals) are shared by all turtles.
    • 
              
  • WHO is a turtle's number. Turtle 0 is the original; launched turtles count up from 1. TURTLES is how many exist.
    • 
              
  • DIE ends the turtle and removes it from the screen; its drawing stays. A launched turtle that finishes its list without DIE stays visible. On turtle 0, DIE just hides it and stops.
    • 
              
  • WAIT n pauses only the calling turtle, for n sixtieths of a second. WAIT 0 just hands over to the other turtles, which keeps turtles that interact in lockstep (see Pursuit and Billiards).
    • 
              
  • POSOF n outputs turtle n's position as [x y], so turtles can follow or avoid each other: SETH TOWARDS POSOF 1.
    • 
              
  • The limit is 2048 turtles.
    • 
            

          


          

            
Speed

            
    
              
  • Turtle: one step per turtle per frame. Good for watching how a program works.
    • 
              
  • Fast: 120 steps per turtle per frame.
    • 
              
  • Warp: runs flat out for 12 ms of every frame, then draws. Use it for big pictures; the command center reports total time when the last turtle finishes.
    • 
            

            
A step is one move, turn, DOT or loop pass. Calculations that never touch a turtle cost nothing in steps, which is why the Mandelbrot's inner loop is fast at every speed. The bar above the canvas shows live turtle count, total segments and steps per second. Stop or Esc halts all turtles.

          


          

            
Screen & color

            
The screen is 960 × 640 turtle steps with (0, 0) at the center, x to the right and y up. X runs from −480 to 480, y from −320 to 320. Heading 0 points up and increases clockwise. Turtles can leave the screen; there's no wrapping.

            
SETPC and SETBG take a palette number 0–15 or a [r g b] list with 0–255 values. To compute a color, build the list with (LIST r g b), because a bracketed list is literal and isn't evaluated. An optional fourth number is opacity.

            

            
SETW n sets pen width in steps. DOT stamps a square the size of the pen width at the turtle, even with the pen up. PE erases with the pen, and PPT or PD returns to painting.

          


          

            
Language

            
    
              
  • Procedures. TO NAME :a :b starts one, with inputs on the same line, and END finishes it. OUTPUT value returns a value, and STOP returns without one. Names are case-insensitive.
    • 
              
  • Variables. MAKE "x 5 sets and :x reads. LOCAL "x makes a variable private to the procedure.
    • 
              
  • Arithmetic. + - * / are infix with the usual precedence. Comparisons are = < > <= >= <>. Parentheses group.
    • 
              
  • Inputs grab whole expressions, as in all Logos. FD 10 + 5 moves 15, and SIN 30 + 60 is SIN 90. Use parentheses when you mean otherwise: (SIN 30) + 60.
    • 
              
  • Minus. :a - 1 subtracts and :a -1 is two separate values. A minus right after a space and touching the next thing is a negative sign.
    • 
              
  • Extra inputs. Wrap a call in parentheses to give more inputs than usual: (LIST 1 2 3), (SUM 1 2 3 4), (PRINT "a "b :c).
    • 
              
  • Words and lists. "word is a literal word, and [a b c] is a literal list. ; starts a comment.
    • 
              
  • Angles are in degrees everywhere, including SIN, COS, ARCTAN, TOWARDS and HEADING.
    • 
            

          


          

            
Primitives

SETXY x y · SETX · SETY · SETPOS [x y]Move to a point, drawing if the pen is down.

              
SETH deg · HOMESet heading; go to the center facing up.

              
PU PD PE PPTPen up, down, erase, paint.

              
SETPC c · SETW n · SETBG c · DOTPen color, pen width, background, stamp a square.

              
HT ST · CS · CLEANHide or show turtle; clear and home; clear only.

              
XCOR YCOR HEADING POS PENDOWNPTurtle state.

              
TOWARDS [x y] · DISTANCE [x y]Heading to, and distance from, a point.

              
LAUNCH [ ] · WHO · TURTLES · POSOF n · DIE · WAIT nConcurrency. See Many turtles.

              
REPEAT n [ ] · REPCOUNT · FOREVER [ ]Loops. REPCOUNT counts from 1 in the innermost REPEAT.

              
IF c [ ] [ ] · IFELSE c [ ] [ ]Conditionals. The second list on IF is optional.

              
WHILE [c] [ ] · UNTIL [c] [ ]Condition is rechecked before each pass.

              
FOR [i a b step] [ ]Counted loop; step defaults to ±1.

              
MAKE "x v · LOCAL "x · OUTPUT v · STOPVariables and returning.

              
SUM DIFFERENCE PRODUCT QUOTIENTPrefix arithmetic.

              
REMAINDER MODULO MINUS ABS INT ROUNDREMAINDER keeps the sign of the first input; MODULO is always ≥ 0 for a positive divisor.

              
SQRT POWER EXP LN LOG10Powers and logs.

              
SIN COS TAN ARCTAN PITrig in degrees.

              
RANDOM n · MIN MAXWhole number from 0 to n − 1; smallest and largest.

              
AND OR NOT · EQUALP LESSP GREATERPLogic and comparison. TRUE and FALSE are values.

              
LIST FPUT LPUT SE WORDBuild lists and words.

PRINT SHOW TYPE · TIMERWrite to the command center; seconds since Run.

            

          


          

            
How it runs

            
Compiler. The flip side is tokenized and parsed with each procedure's input count known in advance, which Logo's prefix syntax requires. It's then translated to JavaScript source and handed to the browser's JIT. Nothing is interpreted at run time.

            
Turtles as coroutines. Procedures that move a turtle become JavaScript generators. Each move, turn and loop pass spends one step from the turtle's budget; at zero it yields, and the scheduler moves on to the next turtle.

            
Pure procedures. A procedure that never moves, launches or waits (and calls only procedures like itself) compiles to an ordinary function with no yields. ITER, SHADE and HUE in the Mandelbrot are pure, so its inner loop runs as plain floating-point code. A pure loop that runs past 200 million passes without drawing is stopped, so a stuck WHILE can't freeze the page.

            
Drawing. Each line segment is one instance in a WebGL 2 instanced draw: a capsule with antialiasing computed in the fragment shader. New segments are batched and drawn once per frame into a 1920 × 1280 texture that holds the picture, so a frame costs only what changed since the last one. Turtles are drawn on top of that texture every frame.

          


          

            
Differences from LogoWriter

            
    
              
  • Variables are lexically scoped. A procedure sees its own inputs and locals plus globals, not its caller's locals.
    • 
              
  • Instruction lists must be written in place as [ … ]; RUN of a computed list isn't supported.
    • 
              
  • No screen wrapping, shapes, text stamping, multiple pages per file, or TELL/ASK. LAUNCH replaces TELL.
    • 
              
  • Additions: true color, pen width, DOT, thousands of concurrent turtles.
    •
